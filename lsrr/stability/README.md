# `lsrr/stability/` — 수렴 안정화 사다리 (조건부)

## 역할
제안서 §4.3의 예비 장치. **수렴 유도가 실패했을 때** 단계적으로 켜는 처방을 담는다.

> 사다리: Jacobian 정규화 → 스펙트럴 노름 제약 → monotone 재파라미터화

## 경계
- **한다:** 수축성 진단, 정규화 항 제공, 제약된 재파라미터화, 승급 정책.
- **하지 않는다:** 기본 경로에 관여하지 않는다. **기본 설정은 `none`이며, 이 패키지가 꺼져 있을 때 아무 흔적도 남기지 않아야 한다.**

## 왜 기본이 꺼져 있는가 (ADR-007)
처음부터 켜면 두 가지를 잃는다.
1. 감쇠·M 샘플링·깊은 감독만으로 **고정점 수렴이 창발하는지**를 확인할 수 없다. 대규모 루프 모델에서 명시적 수렴 목표 없이 수렴이 창발한 선례가 있으므로, 같은 재료로 같은 일이 일어나는지는 그 자체로 보고 가치가 있는 관찰이다.
2. 진동형 표현의 표현력 손실과 뒤섞인다 — §9가 한계로 선제 명시한 트레이드오프이며, α 스윕으로 정량화하기로 한 대상이다.

## 모듈

| 모듈 | 역할 | 상태 |
|---|---|---|
| `probes.py` | 수축 계수 추정, Δ 궤적의 비감소 구간 비율 — **승급 트리거의 근거 데이터** | 계획 |
| `ladder.py` | 승급 정책, 현재 활성 단 기록 | 계획 |
| `jacobian.py` | Jacobian 정규화 (Hutchinson 추정) — **1단** | 계획 |
| `spectral_norm.py` | 엔진 코어 가중치의 스펙트럴 노름 제약 — **2단** | 계획 |
| `monotone.py` | monotone 연산자 재파라미터화 (수축 보장) — **3단** | 계획 |

## 핵심 계약

```
BaseStabilityConstraint.apply(engine) -> None          # 파라미터화 개입 (2·3단)
BaseStabilityConstraint.penalty(R_m, R_next) -> Tensor # 손실 항 (1단)
```

`composite.py`가 `penalty`를 손실에 더하고, `builder.py`가 `apply`를 조립 시점에 호출한다.

### 승급은 판단이 아니라 기준이다
"수렴이 잘 안 되는 것 같다"로 사다리를 올라가면 실험이 재현되지 않는다. `ladder.py`가 트리거 기준을 고정한다:
- **1단 승급:** Δ 궤적의 비감소 구간 비율이 임계 초과, 또는 `behavior.py`가 `oscillating`/`drifting`으로 분류한 샘플 비율이 임계 초과
- **2단:** 1단 적용 후에도 위 조건 지속
- **3단:** 2단 적용 후에도 지속 (표현력 손실을 감수하는 최후 수단)

**활성 단은 런 메타에 기록되고 모든 표에 병기된다.** 안정화를 켠 런과 끄고 얻은 런을 같은 셀에서 비교하지 않는다.

## 의존
`core`, `engine`. (L1~L2 경계 — `engine`의 파라미터에 개입하므로 `engine`을 안다. `engine`은 이 패키지를 모른다.)

## 레거시 참조
없음. 개정 제안서의 신규 명세다.

## 상태
계획 — **조건부**. 어느 마일스톤에도 속하지 않으며, 수렴 유도 실패가 관측될 때 착수한다.
