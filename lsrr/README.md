# `lsrr/` — LSRR 패키지 루트

## 역할
Layer-State Recurrent Reasoner의 구현 패키지. **패키지 루트에는 조립 코드만 둔다.** 모든 기능은 하위 패키지가 소유하며, 루트는 "어떤 부품을 골라 어떻게 잇는가"만 안다.

## 경계
- **한다:** 설정을 받아 슬롯을 인스턴스화하고 전체 모델로 조립. 조립된 모델의 순전파 계약 제공.
- **하지 않는다:** 어떤 연산도 직접 구현하지 않는다. 루트에 새 `.py`를 추가하고 싶어지면 그것은 어느 하위 패키지의 역할인지 다시 물을 신호다.

## 모듈

| 모듈 | 역할 | 상태 |
|---|---|---|
| `__init__.py` | 패키지 진입점, 버전 | 검증 |
| `builder.py` | 설정 → 슬롯 인스턴스화 → `LSRRModel` 조립. **유일하게 전 슬롯의 구체 타입을 아는 곳** | 검증 |
| `model.py` | `LSRRModel` — 조립된 모델의 순전파/생성 계약 | 검증 |

## 핵심 계약

```
LSRRModel.forward(batch, mode) -> ReasoningTrace
```

`ReasoningTrace`(`core/types.py`)는 다음을 담는다: 최종 로짓, `R⁰`, `R*`, `h_ctx`, `h_fusion`, α 가중, 사이클별 진단, 사이클별 판독 결과(깊은 감독·anytime용), 정지 사이클.

**금지:** `ReasoningTrace`에 모듈 객체(융합 헤드, 판독 경로 등)를 싣지 않는다. 레거시가 `model_outputs["fusion_head"]`로 하던 일이며, 손실 함수와 판독 경로를 암묵 결합시킨다 (ADR-005). 손실이 사이클별 로짓을 원하면 훅이 **미리 계산해 값으로** 넣는다.

## 하위 패키지

`ARCHITECTURE.md` §6의 폴더 역할표 참조. 레이어 규칙(§5): 상위 레이어는 하위 레이어만 import하고, 같은 레이어끼리는 import하지 않는다. 조립은 L4(여기)에서만.

## 레거시 참조
`Legacy_LSRR/lsrr/model.py` — 슬롯 조립과 `d_model` 단일 해석 지점 아이디어는 계승. 단 `_resolve_d_model`의 `d_model = d_in` 강제는 폐지한다 (ADR-003: 융합 앵커가 백본 원본 공간으로 이동해 `d_model`이 자유로워졌다).

## 상태
**검증** — M3 완료. `builder.py`가 전 슬롯과 `CycleRunner`·손실까지 조립하고, `model.py`가 인코딩→메모리→정제→판독 전 경로를 잇는다.
