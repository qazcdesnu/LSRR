## 마일스톤

### M0 — 문서와 골격 ✅
아키텍처 문서, ADR, 폴더 역할 부여, 모듈 인덱스, 폴더별 README. **코드 없음.**
*완료 조건:* 모든 폴더에 README가 있고, 모든 슬롯이 `ARCHITECTURE.md` §3 표에 등재됨.

### M1 — 계약 층 (`core`, `config`) ✅
인터페이스·데이터 타입·레지스트리·불변식 단언·설정 스키마와 검증.
*완료:* 더미 슬롯으로 조립 루트가 끝까지 통과(스모크 11종). 설정 오류 12종이 로드 시점에 잡힘. 테스트 80종 통과.
*부산물:* 계약 테스트 I2·I3·I5·I8이 계약 층만으로 구현 가능해 먼저 들어갔다 (I1·I4·I6·I7은 실제 백본·데이터를 요구하므로 M2~M3).
*왜 먼저인가:* 계약이 흔들리면 아래 모든 것을 두 번 만든다.

### M2 — 백본 경로 (`backbone`, `data` 일부) ✅
동결 로드·해시, 1회 순전파 → `ContextBundle`(H_last, H_pool, kv, h_ctx), 연속 디코딩, 프롬프트 규약.
*완료:* 엔진 없이 `h_ctx`만 주입해 GPT-2가 질문 의존적 생성을 낸다. 계약 테스트 I1·I2·I4·I6·I8 통과(45종). 전체 122종 통과.
*발견 (M2가 존재한 이유):* 주입 벡터의 노름이 백본 입력 임베딩 대비 **약 77배**로 분포 밖이었다. 보정 없이는 백본이 질문과 무관한 동일 출력을 낸다. → ADR-011(좌측 패딩), ADR-012(풀러 소유권), ADR-013(노름 보정 기본화).
*미해소 위험:* 단일 위치 주입의 대역폭이 제한적이다(주입 벡터 셔플 시 첫 토큰 분포 총변동거리 0.0145). M3의 첫 관문은 손실 하강이 아니라 **주입 통로가 실제로 학습되는지**다.
*왜 여기인가:* ADR-001/002가 이 코드베이스의 최대 미검증 가정이다. 엔진을 만들기 전에 주입 통로가 실제로 작동하는지부터 확인한다. **주입 통로가 학습되지 않으면 그 아래 전부가 무의미하다.**

### M3 — 최소 학습 루프 (`memory`, `engine`, `recurrence`, `readout`, `objectives`, `runtime`, `telemetry`) ✅
per-layer 어댑터 + `mlp_onepass` 엔진 + 고정 M + `answer_nll`만.
*완료:* 곱셈 합성에서 손실 7.38 → 2.19, 런 디렉터리·스냅샷·체크포인트 왕복 모두 작동. 학습 파라미터 3.3%(§5의 "3% 이내"). 테스트 204종 통과.
*첫 관문 통과 (ADR-013):* 주입 통로가 질문별로 학습된다 — 셔플 대비 첫토큰 **+5.60 nats** (F-009). 단 125스텝 시점에는 +0.05였으므로 **조기 판정을 하지 않은 것이 결정적이었다**.
*새 도구:* `scripts/diagnose_injection.py` — teacher-forcing 손실 하강은 주입 학습의 증거가 못 되므로(F-010) 개입 비교로 판정한다. Phase 0 게이트 판정 전 필수.
*주의:* 이 단계의 `mlp_onepass`가 곧 Phase 0 게이트 ③의 **비교 대상**이다. 베이스라인을 먼저 만드는 것이 순서상 옳다 (ADR-009).

### M4 — 정제 엔진과 사이클 축 (`engine/core_hydra`, `recurrence` 전체, `termination`)
quasiseparable 양방향 스캔, 감쇠·재주입·사이클 임베딩, M 샘플링, TBPTT, Δ<ε 종료.
*완료 조건:* 계약 테스트 I3·I4·I5 통과. Δ⁽ᵐ⁾ 궤적이 기록된다.
*레거시 조치:* 엔진 이식 충실도 검증이 끝나면 레거시 `runs/`·`caches/`(8.3GB)의 참조 가치가 소멸한다 — 삭제한다.

### M5 — 감독과 진단 (`objectives/deep_supervision`, `metrics`, `gates`)
답-앵커형 깊은 감독, anytime 곡선, 비용 회계, Phase 0 게이트 판정기.
*완료 조건:* `scripts/check_gates.py`가 ①~④에 대해 PASS/FAIL을 낸다.

## Legacy_LSRR 폐기 계획

> `Legacy_LSRR/`은 **읽기 전용 참조 구현**이며, 원격 **`main` 브랜치가 그 정본**이다(저장소 루트 = 레거시 구현, 커밋 `8a3fe34`). 따라서 로컬 사본은 언제든 지워도 되고, `v1.1` 브랜치는 이를 추적하지 않는다. 다시 필요하면 `git show main:<경로>`로 꺼내 본다.

### 규모 (2026-09-10 측정)

| 구성 | 크기 | 참조 가치 |
|---|---:|---|
| `runs/` (체크포인트·로그) | **7.7 GB** | 낮음 — 디코딩 경로가 달라 신규 결과와 비교 불가 (ADR-001). 단 M4까지 **엔진 이식 충실도 대조**에 쓸 수 있다 |
| `caches/` (H 캐시) | **644 MB** | 없음 — 캐시 키 규약이 바뀌었고(`H_pool` 추가) 어차피 재생성 대상 |
| 소스·설정·테스트·문서 | **약 1.6 MB** | 높음 — 이식·개작의 원본 |

### 폐기 시점

| 시점 | 조치 | 회수 용량 |
|---|---|---|
| **M4 완료 후** | `runs/`·`caches/` 삭제 | 8.3 GB |
| **M7 완료 후** | `Legacy_LSRR/` 전체 삭제 | 1.6 MB |

- **M4 시점:** 엔진 이식 충실도 테스트(`tests/unit/test_hydra_port_fidelity.py`)가 통과하면 레거시 체크포인트의 대조 가치가 소멸한다. 그 전에는 `runs/`를 남겨 둔다.
- **M7 시점:** `LEGACY_MAP.md` §1·§2의 이식/개작 항목이 전부 `검증` 상태가 되면 소스 참조도 끝난다. 아카이브는 만들지 않는다 — 원본이 다른 경로에 있다.
- 게이트 ③이 FAIL이어서 아키텍처를 재검토하는 중이라면 레거시가 독립 대조 구현으로 유용하므로, 재검토가 끝날 때까지 삭제를 미룬다. (지웠더라도 원본을 다시 받으면 된다.)

## 만들지 않는 것 (범위 밖 명시)

게이트 이전에 다음을 만들지 않는다. 만들고 싶어지면 그것은 게이트를 회피하려는 신호다.

- 분산 학습 / 멀티 GPU 오케스트레이션
- 하이퍼파라미터 자동 탐색 (수동 스윕으로 충분)
- 서빙·추론 최적화 (커스텀 CUDA 커널 포함)
- 웹 대시보드
- 외부 베이스라인 재구현 — §6.2 방침대로 **핵심 주장이 걸린 셀에 한해 최소화**하며, 나머지는 공표치 인용
